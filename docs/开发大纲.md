# Tibo-Reset-EveryDay 开发大纲

更新日期：2026-10-08  
状态：第一版已开发并部署，已启用每 70 分钟同步的定时任务。采集与持久化已完成云端验证，界面已完成重点层级优化及电脑、手机端验收。

网站：[Tibo-Reset-EveryDay](https://tibo-reset-everyday.rainy-shell-2310.chatgpt.site)（公开访问，无需登录；同步写入需要独立授权）。

## 1. 项目目标

开发一个简洁的消息列表网站，汇集 Tibo 的主要额度重置消息，方便查看最近公告的原文和中文翻译。

以用户指定的 [Codex Resets 中文页面](https://codex-resets.com/zh-CN)为主要来源，复用该站已经整理的消息与译文。根据最新要求，网站每 70 分钟同步一次，保存最近 15 条相关消息。首版覆盖范围以该站收录内容为准。

## 2. 已确认的需求

| 项目 | 开发要求 |
| --- | --- |
| 网站名称 | Tibo-Reset-EveryDay |
| 数据来源 | Codex Resets 中文页面及同站公开数据接口 |
| 同步频率 | 云端每 70 分钟执行一次，页面关闭后仍能更新 |
| 保留数量 | 最近 15 条主要额度重置相关消息；不足时展示实际数量 |
| 排序 | 按消息时间从新到旧排列，标星不改变顺序 |
| 标星 | 原文明确提及额度 reset 的消息显示 ★，做适度视觉突出 |
| 双语内容 | 中文在上，英文原文在下，同时提供原帖链接 |
| 时间显示 | 北京时间，精确到分钟 |
| 界面 | 单页消息列表，适配电脑和手机 |
| 同步失败 | 保留已有内容，并显示同步延迟及最近成功同步时间 |

## 3. 数据获取与整理

### 3.1 来源与提取方式

- 中文消息：提取 [指定中文页](https://codex-resets.com/zh-CN)中“Codex 重置公告”的内容。
- 英文消息：优先使用已验证可读取的 [同站公开 JSON 接口](https://codex-resets.com/api/v1/resets)，获取正文、记录时间和原帖链接。
- 若实际开发时确认同站提供可用的中文结构化接口，优先使用它；否则解析中文页面的公告列表。
- 通过原帖链接或记录 ID 匹配中文与英文，避免将不同消息的译文拼接在一起。
- 仅提取消息内容及必要元数据，保留来源链接。广告、统计、预测和互动内容不进入本站消息列表。

### 3.2 消息处理规则

1. 获取来源中最新收录的相关消息，必要时翻页补齐候选记录。
2. 校验正文、原帖链接和时间，依据记录 ID 或原帖链接去重。
3. 匹配中文与英文原文，对已有记录的内容修订同步更新。
4. 检查英文中的 `reset`、`resets`、`resetting` 等重置表达及常见拼写变体，并结合额度语境决定是否标星。
5. 依消息时间倒序保留最新 15 条，原子更新数据库，随后更新最近成功同步时间。

标星表示“明确提及额度重置”，不表示已执行；保留正文中的预告、条件和否定表达。对于来源收录的间接确认消息，原文没有明确重置表达时正常展示，不自动标星。

优先复用来源已有的中文译文。无法匹配时显示“中文译文暂未提供”，后续同步时补齐，首版不强制依赖付费翻译服务。原文若被来源截断，保留实际取得的内容并标明“来源内容可能不完整”，提供原帖链接，不自行补写。

来源时间若属于首次观察或收录时间，应注明其含义，不冒充 Tibo 发帖时间。来源自身的抓取时间也不作为消息发布时间。

## 4. 页面布局

页面由标题、同步信息和消息列表组成。

UI 优化采用深色标题区、金色 reset 星标与侧边线、最新消息标签、中文重点词高亮和独立英文阅读区。布局保留单列消息列表，星标不改变时间顺序。

```text
Tibo-Reset-EveryDay
最近成功同步：2026-10-08 14:30（北京时间）

★ 2026-10-08 11:44
中文消息内容
英文原文内容
查看原帖

2026-10-07 11:35
中文消息内容
英文原文内容
查看原帖

……最多 15 条

数据来源：Codex Resets
```

以上时间与内容仅为布局示意。

- 使用清晰字体、适度留白和简单分隔线。
- 标星消息使用星形图标和轻量边框突出，不仅依赖颜色区分。
- 长消息保持换行，所有内容均可读，链接可直接打开。
- 手机端使用单列排列，避免横向滚动。
- 空列表显示“暂未获取到消息”；首次获取失败显示“数据暂不可用”。

## 5. 技术与数据存储

建议使用 React + TypeScript 构建页面，由服务端负责采集和数据库操作，使用 Sites 托管及 D1 持久化数据。页面读取数据库中的已同步结果，浏览器刷新不直接触发对来源网站的采集。

### 5.1 消息记录

| 字段 | 用途 |
| --- | --- |
| id | 来源记录的唯一标识 |
| original_url | Tibo 原帖链接，同时用于去重与双语匹配 |
| message_at | 消息时间，内部统一保存为 UTC |
| time_kind | 发布时间或首次观察时间等来源时间含义 |
| text_en | 来源提供的英文原文 |
| text_zh | 匹配到的中文译文，可为空 |
| is_reset_mention | 是否明确提及额度重置 |
| content_incomplete | 是否已识别来源内容不完整 |
| updated_at | 本站最后更新该记录的时间 |

数据库仅保留最新 15 条消息，另存最近成功同步时间、最近尝试时间和任务状态。排序以消息时间为准，原文或译文的更新不将旧消息顶到列表首位。

### 5.2 定时同步

- 采用云端定时任务，每 70 分钟运行一次，时区为 `Asia/Shanghai`，连续运行，不固定在每小时整点或半点。
- 任务执行流程：读取来源 → 校验与匹配 → 去重与标星 → 排序裁切 → 保存 → 读取确认。
- 防止两个采集任务同时写入；相同内容重复同步不会产生重复消息。
- 超时、限流或来源不可用时进行有限重试，失败后保留上次有效内容。
- 页面展示最近成功同步时间及延迟状态，避免将“本次尝试时间”显示为成功更新。

## 6. 开发步骤

1. **验证数据来源**：确认中文内容可持续读取，检查英文接口字段、分页方式、双语匹配及时间含义。
2. **实现采集和存储**：完成提取、去重、修订更新、标星和最新 15 条保留规则。
3. **完成简洁页面**：显示同步信息及双语消息列表，检查电脑和手机阅读效果。
4. **接入云端定时任务**：确认页面关闭后仍能采集，核实失败重试和缓存保留。
5. **部署与验收**：验证线上读取、持久化和连续两次同步，不以仅创建定时任务作为自动更新成功的依据。

## 7. 验收标准

- [ ] 网站名称为 Tibo-Reset-EveryDay。
- [ ] 来源与用户指定站点一致，保留来源和原帖链接。
- [ ] 云端任务按每 70 分钟的计划运行，页面关闭后仍能更新。
- [ ] 保存最近 15 条相关消息，不足时不补造记录。
- [ ] 消息按时间倒序排列，无重复，星标不改变顺序。
- [ ] reset 标星依据原文及额度语境，间接确认不误标。
- [ ] 有译文的消息同时显示中文与英文，缺译文或内容不完整时如实标注。
- [ ] 同步失败时已有消息仍可阅读，最近成功同步时间保持准确。
- [ ] 电脑与手机端均可正常阅读和打开原帖。

## 8. 实施边界

首版依赖 Codex Resets 已收录的数据，不承诺覆盖 Tibo 的全部社交动态或全部回复。每 70 分钟是本站的同步频率，来源自身的更新延迟会影响本站获取新消息的时间。

本项目不直接使用 X API；正式实施前先验证来源访问与双语匹配，不将免费公开接口视为永久可用的服务承诺。
