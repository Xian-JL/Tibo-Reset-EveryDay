# 公开部署说明

## 目标

让访客无需登录即可阅读消息，同时保留每 70 分钟更新，避免匿名访客触发采集或修改数据库。

## 访问边界

| 路径 | 访问方式 |
| --- | --- |
| `/` | 公开阅读 |
| `/api/messages` | 公开读取已保存的双语消息 |
| `POST /api/sync` | 需要 `X-Tibo-Sync-Key`，缺少或错误时返回 401 |

服务端未配置有效 `SYNC_AUTH_SECRET` 时返回 503，并拒绝采集及数据库写入。密钥仅存于 Sites 加密环境变量，前端不提供同步按钮或密钥输入功能。

## 发布顺序

1. 完成独立写入授权的代码和测试。
2. 配置服务器加密密钥，更新原有云端任务的请求头，不改变 70 分钟周期。
3. 部署并验证授权同步正常。
4. 把同一站点的访问范围改为公开。
5. 验证匿名首页与消息接口可用，匿名写入被拒绝，授权更新及数据读回正常。

## 云端任务说明

原定时任务已由所有者更新说明并启用，周期仍为每 70 分钟，服务器 `SYNC_SCHEDULE_PAUSED=false`。以后暂停任务时，需同步把这个环境变量改为 `true` 并部署，页面会显示暂停提示；恢复时按相反流程操作。

更新本站的 Tibo 额度重置消息。本站允许公开阅读，但 `POST /api/sync` 必须独立授权。通过所有者可用的 Sites `get_site` 读取本站当前地址和平台服务访问凭证，将凭证同时用于 `OAI-Sites-Authorization: Bearer` 请求头以及 `X-Tibo-Sync-Key` 请求头，调用本站 `POST /api/sync`，再 `GET /api/messages` 核实最近 15 条消息与成功同步时间。

凭证仅发送到本站，不写入源码、日志或任务提示。未提供服务凭证或授权失败时报告问题，不尝试匿名写入。已有同步正在执行时不重复采集；其他瞬时失败最多重试一次，保留缓存。正常运行及内容没有变化时保持安静，仅在持续失败或需要用户处理时报告。
